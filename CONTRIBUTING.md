# Contributing

How to build, test and format the package of this repository. Using it is described in its README,
[`@jsfi/typst-wasm`](packages/typst-wasm/README.md); the [README](README.md) introduces it.

| Directory                 | What it holds                                                           |
| ------------------------- | ----------------------------------------------------------------------- |
| `src/`                    | The Rust crate `@jsfi/typst-wasm` is built from                         |
| `patches/`, `vendor/`     | Patched dependencies: the patches, and the crates generated from them   |
| `pkg/`                    | The built `@jsfi/typst-wasm`, generated by `build.sh`                   |
| `packages/typst-wasm/`    | The README of `@jsfi/typst-wasm`, which `build.sh` copies into `pkg/`   |
| `scripts/`                | The build's helpers: rustup's `cargo`, `vendor/`, assembling `pkg/`     |
| `NOTICE`, `licenses/`     | This project's notice and Typst's, which `pkg/NOTICE` is assembled from |
| `about.toml`, `about.hbs` | The licenses `cargo-about` accepts, and how it writes them              |

## Build

Needs Node 22.12 or newer, the rustup toolchain pinned in `rust-toolchain.toml` (it brings the
`wasm32-unknown-unknown` target and rustfmt), `wasm-opt` from binaryen, and two cargo tools in exact
versions: `wasm-bindgen-cli` in the version of the `wasm-bindgen` crate in `Cargo.lock`, and
`cargo-about` for the third-party licenses. `build.sh` checks both before it builds and, when one is
missing or another version, names the command that installs the right one. On macOS with Homebrew:

```sh
brew install rustup binaryen
./build.sh                   # -> pkg/, once the cargo tools it names are installed
npm install                  # links pkg/ as @jsfi/typst-wasm into the workspace
```

Elsewhere, install rustup with its installer and binaryen with the system's package manager. The
scripts find rustup's `cargo` through `scripts/toolchain.sh`: in `~/.cargo/bin`, where the installer
puts it, or in Homebrew's keg-only `opt/rustup/bin`.

`pkg/` holds `typst_wasm.js`, `typst_wasm_bg.wasm`, the `.d.ts` files, Typst's default fonts in
`fonts/` with their list in `fonts/index.json` and their URLs in `fonts/index.js`, a `package.json`
for `@jsfi/typst-wasm` (written by `scripts/assemble-package.mjs`, which `build.sh` runs), the README
and the license files (`LICENSE`, `NOTICE`, `THIRD_PARTY_LICENSES.md`), ready for `npm publish`.

The build is optimized for speed, so that the module compiles documents fast: `opt-level = 3` and
`wasm-opt -O3`. Optimizing for size instead (`opt-level = "s"`, `wasm-opt -Os`) made the module about
13% smaller and compiling a large document about 15% slower. The module's size is in its README.

## Tests

```sh
cargo test --manifest-path vendor/krilla/Cargo.toml --target-dir target/krilla-tests --lib object_streams
```

Nothing checks the facts the READMEs repeat, such as the version table or the PDF options
table; update them by hand with the code.

The `cargo test` command tests the object-stream patch, comparing every object of a krilla document
before and after the rewrite (see _Patched dependencies_). It runs on `vendor/`, which `scripts/vendor.sh`
creates (and `./build.sh` before it builds).

## Formatting and linting

The JavaScript, TypeScript, JSON, TOML and Markdown files are formatted by oxfmt and linted by oxlint,
both through Vite+ (`vite-plus`): tabs, single quotes, sorted imports, formatted JSDoc and closing
brackets on the last line, and type-aware linting with the unicorn, typescript and oxc rules. The
settings are `oxfmt.config.ts` and `oxlint.config.ts`, which `vite.config.ts` imports for `vp`. The Rust
sources in `src/` follow rustfmt's defaults (`cargo fmt`, pinned with the toolchain); `vendor/` is left
as its crates wrote it.

```sh
npm run format         # rewrites the files, Rust included
npm run format:check   # fails on any file that is not formatted
npm run lint
```

## Versions and dependencies

The package follows semantic versioning. Its version comes from `Cargo.toml`, and the Typst it
bundles from `Cargo.lock` into its description. The table in the README pairs them, and has to
follow every release. Every dependency of the code is pinned to an exact version, and so are the
build tools that shape the output, `wasm-bindgen-cli` and `cargo-about`, whose versions `build.sh`
checks. Node and binaryen only have to be recent enough.

## Patched dependencies

The build compiles against patched copies of two crates, from `patches/`: `krilla.patch` writes object
streams, and `typst-pdf.patch` sets the new setting. Why is in the README's _Smaller PDFs_.

### The object-stream patch

`krilla.patch` adds `SerializeSettings::object_streams` and `src/object_streams.rs`. Once krilla has
written a document, the rewrite moves every object that is not a stream, except the document information
dictionary, into object streams (PDF 1.5) of `OBJECTS_PER_STREAM` objects each, compressed as krilla
compresses its streams, and replaces the cross-reference table by a compressed cross-reference stream
whose rows the PNG Up predictor reduces to differences; the module's constants and their comments give
the numbers and why. The result is as small as qpdf's rewrite of the same file. The PDF's content is
unchanged, object for object; only its storage differs, which readers have understood since PDF 1.5
(2003). krilla leaves a document as it wrote it below PDF 1.5 (so for PDF 1.4 and PDF/A-1), when it must
be ASCII-compatible and when it is `pretty`, as the setting's documentation says. `typst-pdf.patch` only
sets the new field, since typst-pdf builds its settings field by field.

`vendor/` is generated, never the source of truth: `scripts/vendor.sh` downloads the pristine crates
from crates.io at the versions `Cargo.lock` pins, checked against the index's checksums, and applies
the patches; `build.sh` reruns it whenever a patch is newer than `vendor/`.

```sh
scripts/vendor.sh          # fresh vendor/ from crates.io plus patches/
# edit files under vendor/
scripts/vendor.sh --diff   # write vendor/ back into patches/
```

To upgrade Typst, raise the versions in `Cargo.toml` and run `scripts/vendor.sh`. A patch that no longer
applies fails loudly; redo its change on the new sources and write it back with `--diff`. Then run the
object-stream tests (see _Tests_).

### Drawbacks of the object-stream patch

The patch stays downstream on purpose: it is shaped by this module and is acceptable only here; it
is not part of Typst. Upstream,
krilla's maintainer is designing object streams differently ([pdf-writer#79](https://github.com/typst/pdf-writer/pull/79)):
built per chunk inside pdf-writer and compressed in parallel. Drop the patch once a krilla release writes
object streams itself. Until then, it carries these costs:

- **It rewrites the finished file.** krilla first writes the whole PDF, then the patch reads pdf-writer's
  own output back by its layout (`N 0 obj` at the recorded offset, `/Size` first in the trailer) and
  writes it again. The format is coupled to the pdf-writer version `Cargo.lock` pins; a pdf-writer update that changes it makes
  the tests fail, but in a release build, which is what `build.sh` produces, the rewrite then silently
  gives up and tagged PDFs are back at their unpatched size. Run the tests after every dependency
  update.
- **It holds the document twice.** The uncompressed PDF and its rewrite exist side by side, which
  is far below the module's peak memory.
- **It compresses on one thread.** Native Typst builds its PDF with rayon; this pass is serial. WebAssembly
  here has no threads, so nothing is lost in this module, but a native build would pay the full time.
  It is short: zlib-rs packs the 155,000 objects of a private 249-page report of tables in about 0.1 s
  natively, and its tagged export takes about 0.5 s longer than before the patch.
- **It changes krilla's public API.** `SerializeSettings` gains a field, which breaks every crate that
  builds it field by field; typst-pdf needs its one-line patch for that reason.

Compression level 9 instead of krilla's 6 would shave another 15 KB (0.3%) off that report for 45% more
compression time, so the patch keeps 6.

## A minimal build

A build without what most documents never use is half the size of the full build made the same way;
measured for 0.1.0 (Typst 0.15.1), 14.3 MB optimized for speed and 11.7 MB optimized for size (3.4 MB
with brotli). It was built and verified once and is not kept; this is how to make it again.

### What it leaves out

- **Bibliographies and citations:** `#bibliography`, `@key` and `#cite` fail with "bibliographies are not
  supported by this build of Typst". `set bibliography(style: ..)` alone still compiles, so templates
  that set a style keep working.
- **WebAssembly plugins:** `plugin(..)` fails with "WebAssembly plugins are not supported by this build of
  Typst".
- **Syntax highlighting:** code blocks render unhighlighted. Typst's own `typ`, `typc` and `typm` stay
  highlighted, and `raw(syntaxes: ..)` still loads a syntax the document brings.
- **Hyphenation beyond German and English:** text in other languages is not hyphenated, without an error.
- **JPEG, GIF and WebP images:** `image(..)` fails with "JPEG images are not supported by this build of
  Typst", and likewise for GIF and WebP.
- **PDF files as images:** `image(..)` fails with "PDF images are not supported by this build of Typst".

Everything else, PNG and SVG images included, rendered exactly as in the full build: the private 249-page report
came out with identical text, the same size and in the same time. One gap is silent: a JPEG, GIF or WebP
embedded _inside_ an SVG (as a data URI) is dropped from PDF output without an error, because krilla-svg
skips images it cannot decode.

### How to build it

Give it a Cargo package of its own, so that the patches never reach the normal build: a directory such
as `minimal/` with a `Cargo.toml` that copies this one's `[dependencies]` and profiles, points
`[lib] path` at `../src/lib.rs`, and sends `typst-library`, `typst-layout`, `typst-pdf`, `typst-svg` and
`krilla` through `[patch.crates-io]` to vendored copies. Start those copies from `vendor/` for krilla and
typst-pdf, so the object-stream patch stays, and from Cargo's registry for the other three; copy
`Cargo.lock` along. Build it like `build.sh` does, with `--manifest-path minimal/Cargo.toml` and a target
directory of its own.

The principle of every change: keep the public types, so that nothing downstream has to change, but make
the values that need the removed code impossible to create. A type becomes an empty `enum`, its methods
`match *self {}`, its constructor an error; the exporters' branches for it then compile but are dead, and
the linker drops what they called.

- **typst-layout**, `Cargo.toml`: `hypher` with `default-features = false` and
  `features = ["alloc", "english", "german"]`.
- **typst-library**, `Cargo.toml`: drop `hayagriva`, `wasmi`, `two-face` and `hayro-syntax`; build `image`
  with `features = ["png"]` only.
  - `foundations/plugin.rs`: `Plugin` becomes an empty enum; `Plugin::module` fails with the plugin
    error, and `call`, `transition`, `into_module` and the `Debug`, `PartialEq` and `Hash` impls match
    on the empty value.
  - `model/bibliography.rs`: `Bibliography` and `Works` become empty enums; `Bibliography::load` and
    `Works::generate` fail with the bibliography error. `CslStyle` becomes a unit struct whose `load`
    accepts any source without reading it, and `CslSource::Named` holds the style name as a string.
    Keep the elements, `RenderedBibliography` and `RenderedEntry`, and `CslLightElem` and
    `CslIndentElem`, which typst-layout's and typst-html's show rules name; delete the rest of the
    engine (preparation, rendering, the `show_*` functions, the introspection and the tests).
  - `text/raw.rs`: `RAW_SYNTAXES` becomes `LazyLock::new(SyntaxSet::new)`.
  - `visualize/image/raster.rs`: the JPEG, GIF and WebP arms of the decoder fail with the image error;
    drop their decoder imports.
  - `visualize/image/pdf.rs`: `PdfImage` becomes an empty enum with `width`, `height` and `page_index`;
    `PdfDocument` goes. In `visualize/image/mod.rs`, the PDF branch of image loading fails with the
    PDF error.
- **typst-pdf**, `Cargo.toml`: `image` with `features = ["png"]`, krilla without its `pdf` feature.
  `image.rs`: the `ImageKind::Pdf` arm becomes `match *pdf {}`, `convert_pdf` goes, and `convert_raster`
  always uses `Image::from_custom` (no JPEG pass-through). `convert.rs`: drop the `KrillaError::Pdf` arm
  and its `PdfError` import.
- **typst-svg**, `Cargo.toml`: `image` with `features = ["png"]`; drop `hayro` and `hayro-svg`.
  `image.rs`: the `ImageKind::Pdf` arm becomes `match *pdf {}`, and `pdf_to_svg` goes.
- **krilla**, `graphics/image.rs`: `from_jpeg`, `from_jpeg_with_icc`, `from_gif` and `from_webp` return
  an error. krilla-svg calls them for bitmaps inside SVGs, so they must stay; their decoders, unused,
  are then not linked. The dependencies stay, since krilla uses zune-jpeg's `ColorSpace` for PNGs too.

Format edited Typst files with Typst's own rustfmt settings so the diffs carry only real changes:
`max_width = 90`, `use_small_heuristics = "Max"`, `chain_width = 70`, `struct_lit_width = 50`,
`use_field_init_shorthand = true`, `merge_derives = false`. Check the result by compiling one document per
removed feature, which must fail with its error and not crash, and one with text, maths, a table, a PNG
and an SVG, whose PDF must come out the same size as with the full build.
